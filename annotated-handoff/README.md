# Native Japanese MVP Annotated UI Handoff

基于已确认的小样和编辑体验制作。统一入口：`index.html`。

## 查看与分享

- 双击 index.html，使用浏览器打开；也可通过本地预览服务器打开。
- 默认查看模式，顶部选择页面或用上一/下一视图浏览。
- 共覆盖 29 个 App 页面；包含弹窗、菜单、会员和收藏状态及长页面下方内容，共 51 个阅读视图、109 条标注。
- 截图已嵌入 HTML，分享 index.html 一个文件即可，不依赖图片目录或网络。

## 编辑

点击「编辑模式」，选中标注后修改编号、名称、说明。拖动标注框移动整条标注；拖文字或编号可独立调整。按住 Shift 拖框只移动框。拖引线或其三个圆点可调整引线。支持新增、复制、删除。

修改自动保存在当前浏览器。点击「下载可编辑 HTML」可保存全部页面的最新标注。下载文件默认仍为查看模式，并保留完整编辑能力。浏览器中的修改不会自动同步给其他人；分享时请使用最新下载文件。

**修改 Native 日本语 MVP = 修改 MVP 本体 + 验证 + 同步对应 Annotated UI 设计交付 + QA。**

除非用户明确说明“本轮只修改 MVP 本体，不同步设计交付”，否则每次 UI、页面、交互或功能修改后，默认自动同步，不需要用户重复提醒或再次确认。

### 标准执行顺序

MVP 本体修改 → 验证本体修改结果 → 更新对应设计交付内容 → 更新对应截图 → 更新/调整对应标注及说明 → 检查引线和标注位置 → 同步相关统计及 README → QA 检查。

### 同步要求

1. 设计交付 HTML 必须以最新 MVP 本体的实际运行状态为准，不允许本体已更新而交付仍停留在旧版本。
2. 只同步本轮实际受影响的页面、状态、截图和标注；不得因局部修改无理由重做整个交付。保留已完成成果和已确认的编辑能力。
3. 新增页面、弹窗、菜单、重要交互状态、新入口或新功能时，判断其是否属于开发人员需要理解或实现的 UI / 功能状态；属于则新增对应视图、实际截图和标注。
4. 删除、替换或改变功能时，检查已有截图、标注、功能说明及页面状态，同步更新失效内容。
5. 仅内部重构且不影响用户可见 UI、交互逻辑或交付内容时，无需更新交付 HTML。
6. 必须保留页面切换、默认查看模式、标注文字编辑、编号与引线独立拖动、新增/复制/删除标注、浏览器保存、下载可编辑 HTML 和单文件分享能力。
7. 截图必须来自最新 MVP 本体实际运行状态；重新生成受影响的截图，不得使用旧截图冒充最新版。无关截图无需重拍。
8. 更新截图后，逐项检查标注编号、文字、引线、指向位置、页面状态及是否遮挡重要 UI，不得只替换图片。
9. 页面数、阅读视图数、标注数等变化时，同步 HTML、README 及相关元数据/配置。核对 `spec.json`、`captures.json` 与 HTML 内嵌数据，避免重建后恢复旧文案或旧顺序。必要时更新对应源码校验基线，不改写历史审计结论。
10. 执行受影响页面的视觉 QA，并检查上述编辑、保存和导出能力；明确记录通过、失败或未验证的项目。

已有用户确认的正式功能目标文案见 `CONTENT_OVERRIDES.md`。不得把这些目标文案当成本体已经实现的证据，也不得自行回滚已确认文案或扩展开发范围。后续同步须如实说明尚存的目标与实现差异；截图仍必须展示实际运行状态。

## 跨发布版本保留手动编辑（2026-09-19）

公开交付使用固定保存键 native-japanese-handoff-user-edits，不得随发布版本更换。按稳定页面 ID 与标注 uid 保存用户修改的字段、增删标注和删页记录；未修改字段读取最新发布内容。同一字段用户修改优先。标注 uid 基于页面 ID 与控件 selector，后续调整名称或编号不得更换已有 uid。build.py 自动应用 persistent-edits.js 与 apply-persistent-edits.py，不得移除。
